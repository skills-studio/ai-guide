# AI CONTROL™ | Практическа бизнес система

Практическа бизнес система на български език за фрийлансъри, соло експерти и малки услугови бизнеси. Продуктът не е AI чат, SaaS платформа или готова услуга за автоматизация.

## Какво включва

- responsive продуктова страница с модули, бонуси, пакети, FAQ и ROI секция;
- първи контролиран AI процес: от базова стойност до измерим пилот;
- ясни секции „За кого е“, „Не е подходящо за“ и „Какво получаваш / не получаваш“;
- продуктово превю, достъпно директно от продуктовите CTA бутони;
- 6 практически нива: стратегия, Prompt Control™, Autopilot™, човешки контрол, Risk Control™ и резултати;
- локално запазване на прогреса в браузъра;
- Prompt Studio с PCTCO генератор и история;
- Control Library™ с 40 филтрирани бизнес шаблона;
- AI Консултант™: локален Brief Builder без API ключ и без AI отговор в сайта;
- AI Control Score и персонализиран план за следващо действие;
- ROI Monitor за месечна и годишна бизнес стойност;
- responsive интерфейс за desktop, tablet и mobile;
- достъпна клавиатурна навигация и reduced-motion режим.
- три отделни GitHub Pages входа за landing, Starter и Pro;
- директни Stripe Payment Links за Starter, Pro и Starter → Pro.

## Стартиране локално

Необходим е Node.js 22 или по-нова версия.

```bash
npm ci
npm run dev:github
```

Отвори адреса, показан от Vite.

## Статичен build

```bash
npm run build:github
```

Готовите файлове се създават в `docs/` и работят без сървърна база данни или API ключ.

Build-ът съдържа:

- `landing_page.html`: публична продуктова страница;
- `basic-guide.html`: Starter версия с 2 Prompt Studio генерации и заключени Pro инструменти;
- `index.html`: Pro версия с пълния инструментариум.

## Публикуване в GitHub Pages

1. Качи проекта в GitHub repository с branch `main`.
2. Отвори **Settings → Pages**.
3. Под **Build and deployment** избери **GitHub Actions**.
4. При всеки push към `main` workflow-ът ще build-не и публикува сайта автоматично.

Можеш да стартираш публикуването и ръчно от **Actions → Deploy AI CONTROL to GitHub Pages → Run workflow**.

## Stripe → GitHub Pages поток

Моделът следва работещата структура на предишното статично издание:

1. Клиентът отваря `landing_page.html`.
2. Бутонът за пакет отваря съответния Stripe Payment Link.
3. След успешно плащане Stripe пренасочва към правилния статичен файл.
4. Starter вижда upgrade линка само вътре в `basic-guide.html`.
5. Upgrade checkout-ът пренасочва към `index.html`.

В Stripe Dashboard настрой **After payment → Redirect customers to your website** така:

| Stripe продукт | Success URL |
|---|---|
| Starter €19.99 | `https://<github-user>.github.io/<repo>/basic-guide.html` |
| Pro €39.99 | `https://<github-user>.github.io/<repo>/index.html` |
| Starter → Pro €20.00 | `https://<github-user>.github.io/<repo>/index.html` |

Подробната контролна карта е в [`STRIPE-GITHUB-SETUP.md`](./STRIPE-GITHUB-SETUP.md).

## Пазарна конфигурация

Цените и трите покупни пътя са централизирани в `components/marketConfig.ts`:

- Starter: €19.99;
- Pro: €39.99;
- Starter → Pro: €20.00;
- `checkout.starter`, `checkout.pro` и `checkout.upgrade` съдържат трите Stripe Payment Links;
- `seller` приема официалните данни на продавача за правните страници и търговската комуникация.

Upgrade checkout линкът не се показва на публичния landing. Той е видим само в Starter версията и при заключените Pro инструменти.

## Данни и сигурност

Прогресът, първият контролиран AI процес, AI Score, историята на промптовете и работните полета се пазят само в `localStorage` на устройството. Няма изпращане към външен AI или backend и няма синхронизация между устройства.

Важно: GitHub Pages е публичен статичен hosting. `noindex`, отделните файлове и скритите CTA бутони не са автентикация. Всеки, който получи платения URL или разгледа публичния repository, може да отвори или копира съдържанието. Този модел е подходящ за бърз пазарен тест с приет риск от споделяне, но не е надеждна защита на платено съдържание.
